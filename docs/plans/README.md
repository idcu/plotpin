## 推进约定

### 指令与范围

- 执行指令格式：`推进 N-xx`；一次只推进一条任务，完成、提交、汇报后立即停止，不自动开始下一条。
- 任务边界以计划正文为准；不得顺手扩大范围、重构无关文件、读取/修改仓库根目录 `camera-*` 文件。
- 必须新增运行时依赖、破坏公共 API、放宽门禁阈值、改变既有导出字段时，先停止并说明，不得自行决定。

### 开工前检查（只读）

```bash
git status --porcelain
git rev-parse HEAD
git log --oneline -5
```

- 工作区必须干净（允许仅未跟踪 `audit-out/`）。若存在上一轮未提交半成品：能补全到可提交则补全，不能则还原到指定提交点，禁止带着脏工作区开工。
- 确认基线提交与计划 §1 一致；不一致时先记录差异，不假设数字。

### 执行闭环

1. 读任务条目，确认证据位置仍成立（行号漂移时以当前代码为准并在汇报中注明）。
2. 实现最小改动；新增逻辑先检索现有公共实现，禁止复制粘贴。
3. 补验收要求的断言/用例；验收点逐条对应，不得用“看起来正常”替代。
4. 跑硬门禁（见下）；性能任务额外跑真实 Chromium before/after 采集。
5. 同一提交更新受影响文档与 `CHANGELOG.internal.md`（Commit Hash、改动点、实测数据、遗留风险）。
6. 本地 `git commit`；**禁止 push**。汇报 commit、实测数据、未完成项与风险。

### 硬门禁（提交前全绿）

```bash
node scripts/check.mjs --selftest
node scripts/e2e.mjs
node scripts/build.mjs --check
node scripts/check-gates.mjs
node scripts/check-discipline.mjs --strict
```

- selftest 断言数不得减少；e2e 通过数不得减少、跳过项不得增加；产物 ≤ 839,680 B（基线 783,226 B，余量 56,454 B）。
- 性能任务必须附真实 Playwright Chromium 的 before/after P95、heapUsed 与采集命令；Node 桩数据不能作为浏览器结论。
- 门禁不绿不得提交；禁止为通过而删断言、加 `skip`、放宽阈值或跳过场景。

### 失败与未验证处理

- 发现缺陷先报告现象与证据，等待确认后再修；不得静默改业务逻辑。
- 当前环境无法覆盖的项（真机、双设备 WebRTC、真实语料、人工标注）明确写「未实测/待验证」并说明所需条件，不得用构造样本或估算值顶替。
- 若任务间存在技术依赖冲突，先说明理由再调整顺序；需要拍板的取舍见计划 §6。

### 提交规范

- 约定式提交：`fix(gate):` / `fix(io):` / `fix(collab):` / `perf(render):` / `test(e2e):` / `docs(plans):` 等。
- Body 必须含实测数据（如断言数、e2e 数、体积、P95、heapUsed）与影响面（公共抽象/调用方）。
- 禁止 `fix bug`、`update`、`optimize` 等无信息提交；禁止水提交与多个任务合并提交。
