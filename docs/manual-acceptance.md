# 人工验收手册（manual-acceptance）

> **读者**：发布前执行验收的人，不需要熟悉代码。
> **回答**：哪些项必须人工验、每项怎么判、失败/阻塞怎么记、历史结论是什么。
> **不回答**：未解决问题状态见 [known-issues](known-issues.md)；自动化测试见 [testing](testing.md)；性能读数见 [performance](performance.md)。
> **铁律**：人工验收不能替代 `npm run ci`、`selftest`、`bench`、`check-gates`；**没做过的不写 PASS**；构造样本、模拟器、CPU 节流、同机双标签、SwiftShader 都不得冒充真机/真语料/跨网络/真实 GPU。

## 1. 判定口径

| 结论 | 含义 |
|---|---|
| `PASS` | 本次设备/语料上所有判据满足，且有证据 |
| `FAIL` | 执行过，至少一条判据不满足（写清现象与证据） |
| `BLOCKED` | 条件不满足未能执行（设备/软件/网络/语料缺失），写明缺什么 |
| `N/A` | 该项在本次范围不适用（如 A1 无旧工程语料） |
| `PROXY` | 代理数据（节流、SwiftShader、同机双标签），不得并入 PASS |

每项结论至少能追溯到一项证据：截图、控制台日志、导出文件、Performance 导出或 CAD 截图。结果与 known-issues 冲突时以 known-issues 为准。

## 2. 环境准备

### 2.1 安全上下文

- `http://localhost` / `http://127.0.0.1` 只对桌面本机算安全上下文；手机通过局域网 IP 访问不算。
- 真机验收必须 HTTPS：把 `dist/plotpin-standalone.html` 部署到 HTTPS 静态站点或使用 HTTPS 隧道。
- Chrome 的 `unsafely-treat-insecure-origin-as-secure` 仅限临时调试，不得据此记 PASS；iOS Safari 无等价开关。
- `node scripts/serve.mjs` 只提供 HTTP（默认 `127.0.0.1:4173`），用于桌面调试与 e2e，不能给真机安全上下文。

### 2.2 协作与 `iceServers`

默认不配中继（`new RTCPeerConnection({ iceServers: [] })`）；可在协作面板配置 STUN/TURN，只存本机键或本次会话（`plotpin.collab.ice.v1`），凭据不进入邀请串、协作消息与工程 JSON：

- 不配中继：同局域网可借助 host candidate 建连；
- 配了中继：跨网络仍取决于 TURN 可达性与鉴权，**跨 NAT 与 TURN 鉴权均未验证**，M3 跨网络部分记 `BLOCKED` 并写明「TURN 未验证」，不得直接记 PASS；
- 面板只显示候选计数（host/srflx/relay）与选中候选对类型，不显示 IP/端口/完整 SDP；
- 同机双标签或同局域网结果不能当跨网络通过。

### 2.4 证据目录

- 统一放 `acceptance-evidence/<编号>/`（已在 `.gitignore`，位于 Playwright `outputDir` 之外）。
- 文件名含日期与设备，如 `acceptance-evidence/M1/M1-20261107-pixel7.png`。
- **不要放 `test-results/`**：Playwright runner 启动会清空该目录，曾因此丢失人工证据。
- 汇总表可放 `acceptance-evidence/results.md`；证据与语料默认不进 Git。

## 3. 逐项验收卡

### M1 真机移动端 PWA（安装 / 离线 / 手势 / 侧栏）

- 设备：Android 10+ + Chrome 120+，或 iPhone iOS 16+ + Safari 17+；桌面仅对照。
- 前置：HTTPS 安全上下文；已生成 `dist/plotpin-standalone.html`。
- 步骤：`node scripts/build.mjs` 生成单文件并部署 → 安装到主屏幕 → 从图标启动，新建工程、放 2 个对象、切一次楼层 → 开飞行模式，杀进程后从图标重开 → 平移/缩放、打开 `☰` 侧栏、点 5 个主要按钮。
- 判据：独立窗口启动；断网重开 5 秒内恢复上次工程，无白屏/错误 toast；平移缩放与侧栏可用；主要触控目标 ≥44×44 CSS px；无未处理控制台异常。
- 失败处理：拿不到 HTTPS/安装入口 → `BLOCKED`；只是浏览器快捷方式而非独立窗口 → `FAIL` 或 `BLOCKED`，不得 PASS。

### M2 桌面 Firefox / Safari 的 SVG 导入、下载、沙箱、PDF

- 设备：Firefox ESR 128+；Safari 17+（macOS 13+）。
- 前置：`localhost` 或 HTTPS；准备含 2 条 `<path>` 的 `sample-symbol.svg`；`plugins/sample-sandboxed.js` 可用。
- 步骤：符号页签导入 SVG 并放置 → 导出 SVG/DXF/PDF → 控制台加载示例沙箱插件 → 导出「沙箱 Markdown 清单」→ 打印预览。
- 判据：SVG 导入成功且符号可见；三种下载扩展名/文件名正确且字节 >0；沙箱插件注册并导出 `.md`；打印预览页数正确、无空白页；控制台无阻断性异常。
- 边界：**自动化 e2e 默认只有 Chromium 入口与证据**。2026-11-14 已用本机 Playwright Firefox 实跑 5 条核心用例（5 passed，见 [testing](testing.md)§3.4），其余用例仍未验证；2026-11-07 的 Firefox 159 / WebKit 27.2 手工记录无留存产物、未复跑，不构成当前通过结论；Safari 原生未验证，不能用 WebKit 结果代替。
- 失败处理：Firefox 失败记 `FAIL` 并写错误；无 macOS 时 Safari 记 `BLOCKED`。

### M3 真实双设备 WebRTC 协作

- 设备：两台设备 + Chromium 120+；同局域网；跨网络需公网出口与 TURN。
- 前置：两台设备都能打开同一 HTTPS 页面；工程已建好。
- 步骤：A 生成邀请（二维码/文本）→ B 连入 → A 增删改，观察 B → B 断网 10 s 改一个对象再联网 → 双方同时改同一对象不同字段 → 跨网络重复。
- 判据（同局域网）：B 在 2 秒内看到 A 的增删改；断网重连后重新同步；无崩溃；冲突按 LWW 且非目标字段不丢。
- 失败处理：同局域网失败记 `FAIL` 并保留双方控制台；跨网络即使配了 TURN 也记 `BLOCKED`，写明「跨 NAT 与 TURN 鉴权未验证，非产品缺陷结论」。

### M4 英文译文语义质量

- 设备：桌面 Chromium；一名中英双语评审人。
- 步骤：设置 → English → 保存 → 逐页走新建/导入/导出/楼层/规则/快照/插件/打印 → 记录仍为中文、占位符未替换、截断、术语不一致 → 切回中文复核。
- 判据：0 条未翻译、0 条残留占位符；主要流程语义可理解、术语一致；截断不遮挡操作；争议逐条记录并给建议译法。
- 说明：自动化只能证明「无中文残留/缺口」，不能证明语义正确；不得以「键存在/非空」代替语义通过。
- 证据：≥8 张英文界面截图 + 问题清单（位置/原文/建议）。

### M5 真实 GPU / 低端设备渲染绝对性能

- 设备：目标真机（Android 10+ / iOS 16+）；桌面 Chromium 仅对照。
- 前置：≥2000 对象的工程；设备开启远程调试。
- 步骤：记录型号/SoC/GPU/系统/浏览器 → 100% 缩放连续平移 10 秒 → DevTools Performance 录制 → 统计 P50/P95/P99 与最长帧 → 桌面 `npm run perf:browser` 保存 JSON 仅作对照。
- 判据：完成 10 秒录制且无单帧 >50 ms；出现长帧即 `FAIL` 并附截图/火焰图。
- 禁止：用 SwiftShader 桌面值或 Node bench 值推断真机通过。

### M6 低端设备上的插件 2 s 超时体验

- 设备：低端 Android（2019–2021 中低端，RAM ≤4 GB）；Chrome 120+；远程调试。
- 步骤：打开页面保持画布可交互 → 控制台执行 3 秒忙循环插件 → 用 `performance.now()` 记录调用到返回时间 → 同时尝试平移画布 → 检查插件是否禁用、导出列表是否移除。
- 判据：主线程不冻结；Promise 约 2–3 秒返回 `{ok:false}`，reason 含「超时」；插件不出现在导出格式；无崩溃。
- 失败处理：无低端机记 `BLOCKED`；桌面 6× CPU 节流标 `PROXY`，不得 PASS。

### M7 大尺寸符号在真实 DXF 查看器中的观感

- 设备：AutoCAD 2020+ 或 LibreCAD 2.2+。
- 前置：`tests/golden/symbol-scene.dxf`；另从应用导出含 2.5 m 球机符号的 DXF。
- 步骤：CAD 打开并 `ZOOM EXTENTS` → 检查 S1/S2/S3 位置/旋转/图层 → 量 2.5 m 符号外接尺寸 → 1:1 检查折线锯齿 → 与 `symbol-scene.svg` 并排比对。
- 判据：无明显断裂/自交/错位；旋转方向与 SVG 一致；2.5 m 符号误差 ≤1%；图层名可读；折线近似可接受。
- 失败处理：查看器打不开 ASCII DXF → `BLOCKED` 并写版本；填充缺失不算失败。

### M8 50 条真实图纸快照差异核对

- 设备：桌面 Chromium；两名熟悉图纸的评审人。
- 前置：50 组真实工程前后版本（不得用构造样本）；匿名化；人工基准在查看应用输出**之前**独立完成。
- 步骤：两名评审人各自列六类差异（新增/删除/属性修改/移动/换楼层/类型变更），分歧由第三人裁定 → 应用「快照 → 对比 A→B」→ 逐类比 TP/FP/FN → 汇总 50 条。
- 判据（执行前由负责人确认）：六类逐类一致率均 ≥95%；「删除」「换楼层」不得漏报；任一条崩溃/无法对比即 `FAIL`。
- 失败处理：语料不足或无人基准 → 整项 `BLOCKED`；禁止构造样本补足。

### 补充-01 Excel / WPS 打开导出文件

- 设备：Excel 2019+ / Microsoft 365；WPS 11+。
- 前置：对象名含中文、引号、逗号、前导 `=`（如 `=1+1`）。
- 步骤：改名 → 分别导出 `.xlsx` 与 `CSV` → 用 Excel 与 WPS 打开 → 检查按文本显示、不执行公式、无 `#NAME?`、特殊字符完整 → 核对行数。
- 判据：名称按文本显示、不执行公式、无 `#NAME?`；特殊字符完整；行数一致；两种软件均可打开。
- 失败处理：只验一种软件写「部分通过」；不得用文件头魔数代替真实打开。

### A1 旧工程图标视觉回归（可选抽检）

- 步骤：`node scripts/selftest.mjs --filter "中英界面|符号库"`（权威判据）→ 有旧 JSON 时导入逐类检查图标 → 与 `tests/golden/legacy-symbols.svg` 对照。

- 失败处理：无旧工程语料 → 人工部分 `N/A`，自动化结果照常记录。

## 7. 与自动化门禁的边界

即使所有人工项全部 PASS，也只说明「当次设备/语料可用」，不能替代：

- `npm run ci`：`check.mjs --selftest` → `bench.mjs` → `build.mjs --check` → `check-gates.mjs`；
- `node scripts/selftest.mjs` 与 `tests/golden/*` 逐字节比对；
- `node scripts/e2e.mjs`（Chromium）；
- `node scripts/perf-browser.mjs`（不进 ci，但仍是可重复数据）；
- A1 的 path 哈希与 `legacy-symbols.svg` golden。

冲突时以 [known-issues](known-issues.md) 为准，并在记录中注明，不得自行改号或改状态。
